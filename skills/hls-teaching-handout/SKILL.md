# HLS Teaching Handout Builder

版本：v1.5.2（正式版 · 教材模式 · PDF 前预览编辑 · 自动归档 · 蓝橙固定封面）

将原始资料制作成**教材式教学讲义**，而不是宣传册、社交媒体卡片或把知识点拆成一页一张的演示文稿。

默认输出应接近大学教材、课程讲义或研究方法手册：

- 正文连续阅读，文字内容优先。
- 标题层级清楚，章、节、小节编号完整。
- 目录详细并可点击跳转。
- 表格、定义框、重点框只在确实有教学作用时使用。
- 页面可以有适度留白，但不得依赖大卡片和装饰组件填充版面。

## 固定封面模板（强制）

从 v1.4 起，讲义封面默认且强制使用海乐思提供的固定封面模板图，不再为每份讲义单独设计新封面。

封面模板规则：

- 第一页必须使用指定封面模板图作为底图。
- 底部蓝橙几何图形、整体构图、左下角 HLS 标识和品牌配色保持不变。
- 允许改动的仅为封面文字内容，不得随意改动装饰图形布局。
- 封面上的主标题、副标题和主题说明，必须根据当前文档内容自动改写。
- 若用户提供明确标题与副标题，优先采用用户提供版本。
- 若用户未提供，则根据原始资料主题自动生成“教材式标题”，要求准确、简洁、非营销化。
- 封面必须出现在目录前，作为 PDF 第 1 页。

默认封面模板资源：

- 封面模板图路径：`assets/hls-cover-template-clean.jpg`
- 封面资源必须相对于 Skill 根目录解析，不得写死为某次运行中的 `/mnt/data/...` 临时路径。
- 若包内资源缺失，才使用用户当前提供的同一模板图，并在编排阶段建立新的资源映射。

封面文案结构默认如下：

```text
顶端小标：学术学习资料
主标题：根据文档内容生成
副标题：根据文档内容生成，可保留英文术语
主题说明：3 个左右关键词或一句概括
```

标题生成原则：

- 主标题优先概括资料主题，不宜过长，通常控制在 10–22 个汉字。
- 副标题用于补充范围、方法或英文术语，例如“从 Critical Analysis 到 Critical Review”。
- 第三行说明用于概括 2–4 个核心主题，使用顿号或中点分隔。
- 标题语气应像教材或讲义，不用广告式表达，不写“速成”“必看”“保姆级”等社交媒体口吻。

技术实现建议：

- 优先复用 `templates/cover-fragment.html` 与 `templates/hls-handout.css`。
- 在 HTML 中将封面模板图作为第一页整页背景图或整页 `<img>`。
- 在图上方叠加可编辑文字层，而不是把标题直接烘焙进位图。
- 文字层需锁定在模板图上半部分的标题区域，保持与模板一致的版式秩序。
- 若输出为 PDF，封面文字应保持为可搜索文本，避免整页 raster 化。

## 核心目标

1. 保留原始资料的知识结构、正文信息、术语、限定条件和来源。
2. 把原始资料重组为可连续阅读的“章—节—小节”教材结构。
3. 自动生成详细目录，至少收录一级、二级标题；存在稳定三级结构时同时收录三级标题。
4. HTML 和 PDF 目录均可点击跳转，PDF 同时生成书签大纲。
5. 正文优先，不为追求“设计感”把段落切成大量组件。
6. 表格统一使用 LaTeX 风格双线表。
7. 生成后执行 PDF 渲染、逐页检查、目录链接检查、密度检查和溢出检查。

## 何时使用

适用于：

- 将 Markdown、Word、PDF 或零散文字整理为内部教材、教学讲义或学习手册。
- 统一已有资料的字号、留白、标题体系、目录、页眉页脚和表格规范。
- 将长篇学术写作指南、课程资料、研究方法资料自动生成 A4 文档。
- 建立海乐思可重复使用的资料生产流程。

不适用于：

- 小红书封面、社交媒体卡片、PPT 演示页。
- 强营销型宣传册。
- 照片拼贴、复杂插画或大量绝对定位的视觉画册。

## 默认技术路线

```text
原始资料
  -> 文本提取与来源映射
  -> 内容模型 content-model.json
  -> 章节层级与目录模型 outline.json
  -> 文档编排计划 document-plan.json
  -> editable-handout.html
  -> 本地浏览器预览编辑
  -> 用户确认 approved-handout.html + EDITOR_APPROVED
  -> CSS Paged Media 两阶段目录页码回填
  -> Vivliostyle PDF
  -> PDF 渲染与 QA
  -> QA 通过后自动归档到 05_最终交付/教学讲义/
```

主排版源文件为 HTML，不把 DOCX 作为默认主源文件。

如果运行环境没有 Vivliostyle，可使用支持 CSS Paged Media 和内部链接的渲染器作为回退方案，但必须在 QA 报告中注明。

## PDF 前预览编辑（强制）

普通生产必须在正式 PDF 生成前启动本地预览编辑器。用户可修改封面文字、标题文字、正文、列表、提示框、表题/图题、来源说明、表头与表格正文单元格，并可调整受控字号、加粗、对齐、行距和手动分页。撤销与重做必须同时覆盖文字编辑和字号、行距、加粗、对齐、段落类型、分页符等格式变化。

以下结构锁定：封面背景与 Logo、目录链接与页码、页眉页脚、标题编号和 `id`、书签层级、内部链接、表格行列及 `thead` 结构。`th` 的文字可编辑，但不得增删表头单元格或移除 `thead`；目录页的来源说明可编辑，但目录项目本身保持锁定。确认时服务器会再次校验锁定结构并清除工具栏、`contenteditable`、事件属性和临时标记。

强制门禁：

- 未检测到有效 `work/EDITOR_APPROVED` 时，`render_pdf.py` 必须拒绝生成正式 PDF。
- 标记包含 `approved-handout.html` 的 SHA-256；HTML 改变后旧标记自动失效。
- 只有自动测试允许显式传入 `--auto-approve-for-test`，普通运行禁止默认开启。
- 本地服务器只允许绑定 `127.0.0.1`，不提供登录、云端保存或多人协作。
- 用户点击“确认并生成 PDF”后，只有 PDF 渲染与 QA 均成功才自动归档；标准内容项目的 PDF、最终 HTML、QA 报告与 QA 摘要进入 `05_最终交付/教学讲义/`，失败结果不得进入最终交付。

# 一、强制原则

## 1. 内容忠实

- 不得擅自添加原资料没有提供的知识、案例、研究数据或引用。
- 不得删除原资料中的适用边界、课程要求、限定条件和来源说明。
- 可调整标题层级、段落顺序和呈现方式，但不得改变原意。
- 新生成的导语、学习目标和总结只能概括原资料已有信息。
- 原文无法支持的内容标记为“原始资料未提供”，不要补写。
- 引用中的作者、年份、页码、原文引号和术语必须保留。
- 面向用户的转换成品禁用“原资料”这一机械化措辞。按语境改用“来源文档”“源文档”“原文”“该指南”“该论文”，或直接写具体文献名称；结构化模型、HTML 与最终 PDF 均不得出现“原资料”。

### 正文保留率

默认以完整教材模式执行：

- 原始正文中的有效知识内容应保留约 80%–100%。
- 不得为了缩短页数，把多个完整段落压缩成一句总结。
- 不得把原文中连续论证拆成互不相连的卡片标题。
- 只有用户明确要求“精简版”“速查版”时，才降低正文保留率。

## 2. 文字内容优先

正文是页面主体，组件是辅助。

每个普通正文页建议：

- 连续正文、标题、列表和表格占有效内容区域的 75%–90%。
- 彩色底框、卡片、标签和装饰区域原则上不超过 10%–25%。
- 同一页通常不超过 1 个明显底色组件。
- 连续两页不得都由多个卡片或网格组件主导。

禁止：

- 把四个步骤自动转成四张卡片。
- 把四个常见问题自动转成四宫格。
- 把每个示例句拆成独立分析卡。
- 为了视觉丰富，把普通段落改成提示框。

## 3. 教材，而非 PPT

默认使用：

- 单栏连续正文。
- 宋体或衬线字体作为中文正文。
- 无衬线字体用于标题、目录和标签。
- 小面积浅色提示框。
- 稳定页眉、页脚和页码。

避免：

- 大面积渐变。
- 阴影、悬浮卡片和圆角堆叠。
- 大图标、编号圆牌、路线图式步骤组件。
- 一页只呈现一个知识点。
- 模块标题占据半页以上。

## 4. 阅读优先

- A4 正文默认 10.8–11pt，不低于 10.5pt。
- 英文长示例不低于 10.2pt。
- 表格正文不低于 9.5pt。
- 不得为了维持固定页数缩小文字。
- 内容多时增加页面，内容少时允许下一章接续在同页下方。
- 不强制每章另起新页；应优先避免上一页只剩少量文字和大面积空白。

## 5. 先结构化，再排版

必须先生成：

- `source-map.json`
- `content-model.json`
- `outline.json`
- `document-plan.json`

排版脚本只消费结构化模型，不直接从原始资料临时拼接页面。

# 二、详细目录与内部跳转

## 1. 目录层级

默认目录收录：

- 一级：章或模块。
- 二级：节。
- 三级：存在明确子结构时收录小节。

目录不得只列模块名称。只要正文中存在编号标题，就应进入目录，除非该标题只是临时提示语或表格标题。

推荐编号：

```text
第一章  批判性写作的基本内涵
1.1 Critical Analysis 的概念与表现
1.2 “写作不够批判”意味着什么

第二章  从描述性改写到批判性分析
2.1 描述性改写：Example A
2.1.1 示例文本
2.1.2 示例分析
```

## 2. 目录样式

目录默认先使用单栏。只有单栏在目标 A4 目录页中确实溢出，且双栏能改善页面利用率时，才显式启用双栏；不得只因目录条目较多就机械切换。双栏目录使用：

- 章标题使用品牌主色和较粗字重。
- 节和小节逐级缩进。
- 标题与页码之间使用点线引导符。
- 页码右对齐。
- 两栏之间使用浅色细分隔线。
- 如果双栏导致页面下半部出现大面积空白，应恢复单栏或调整目录与来源说明的间距，不为双栏而双栏。

## 3. 可点击要求

HTML：

- 每个目录项使用 `<a href="#section-id">`。
- 每个正文标题必须拥有稳定且唯一的 `id`。

PDF：

- 内部链接必须保留。
- 点击目录项应跳转到对应标题所在页。
- 一级、二级和三级标题应生成 PDF 书签。
- 目录页码应通过 `target-counter(attr(href), page)` 或等效机制自动生成，禁止手工猜页码。

示例 CSS：

```css
.toc a::after {
  content: leader('.') target-counter(attr(href), page);
}

h1 { bookmark-level: 1; }
h2 { bookmark-level: 2; }
h3 { bookmark-level: 3; }
```

## 4. 目录 QA

必须检查：

- 目录是否覆盖所有正式编号标题。
- 页码是否与实际页面一致。
- 所有目录链接是否为内部链接。
- 是否存在空链接、重复锚点或跳转到错误章节。
- PDF 是否生成书签大纲。

# 三、正文视觉系统

## 0. 品牌配色（强制）

默认使用海乐思蓝橙色系统：

- 主蓝：`#2450C8`，用于目录标题、章标题、节标题、主要分隔线和重点信息。
- 深蓝：`#1D3FA8`，用于章标题、目录一级标题和需要更高对比度的文字。
- 强调橙：`#E5653A`，用于封面侧边色带、导读标签、定义标签、复选标记和少量关键提示。
- 浅蓝底：`#EEF4FF`，用于本章导读、重点框等低饱和辅助区域。
- 浅橙底：`#FFF4EC`，用于定义框或需要与蓝色重点框区分的提示区域。

使用规则：

- 蓝色是页面主色，橙色只承担强调作用。
- 正文页不得使用大面积橙色底块，单页橙色面积通常不超过有效内容区域的 10%。
- 默认不再使用青绿色、蓝绿色或其他替代主色。
- 表格正文保持黑灰色，表头文字可使用深蓝，不使用彩色表头底纹。
- 配色调整不得改变教材式连续正文、目录层级和页面密度。

## 封面版式规则（强制）

固定封面模板图已经定义了品牌图形，因此 Skill 不再重新设计封面背景。封面页只负责：

1. 放置固定模板图。
2. 根据文档内容替换标题文字。
3. 保持封面版式与模板一致。

封面上半区文字规范：

- 左侧蓝色竖线保留。
- 顶端小标默认保留为“学术学习资料”。
- 主标题使用粗体无衬线字，大号蓝色，按 1–2 行排布。
- 副标题使用蓝色粗体，可中英混排。
- 主题说明一行使用较小字号蓝字。

封面文字改写规则：

- 当原文标题过长时，可压缩为更适合封面的教材式标题，但不得改变主题。
- 允许将原文完整标题保留到扉页、目录页或页眉，不要求封面主标题机械复现超长标题。
- 若文档属于某一具体章节，例如“Discussion 写作”，主标题应突出章节主题；副标题再补充范围。
- 若文档是总论型资料，例如“批判性写作”，主标题可为总标题；副标题补充学习路径。

封面实施细节：

- 封面页不显示页眉页脚。
- 封面模板图与文字层共同组成 PDF 第 1 页。
- 目录从第 2 页开始。
- 封面不进入目录，但可以作为 PDF 书签中的第 0 级或“Cover”。

## 1. 字体

推荐：

```text
中文正文：Noto Serif CJK SC / 思源宋体 / 宋体
中文标题：Noto Sans CJK SC / 思源黑体
英文正文：Georgia 或与中文正文协调的衬线字体
英文术语：可保持正文衬线字体，不强制全部加粗
```

## 2. 字号层级

| 层级 | 默认字号 |
|---|---:|
| 封面主标题 | 27–31pt |
| 目录标题 | 25–28pt |
| 章标题 | 19–21pt |
| 二级标题 | 14.5–15.5pt |
| 三级标题 | 11–12pt |
| 正文 | 10.8–11pt |
| 英文示例 | 10.2–10.5pt |
| 表格正文 | 9.5–9.8pt |
| 提示框正文 | 10.2–10.5pt |
| 页眉页脚 | 8.2–8.8pt |

正文行高默认 1.65–1.78。

## 3. 页面网格

默认 A4 竖版：

```text
上边距 18mm
下边距 18mm
左边距 20mm
右边距 18mm
正文有效宽度约 172mm
```

普通正文默认单栏。仅以下内容可使用多栏：

- 目录。
- 词汇索引。
- 明确需要并排比较的短内容。

## 4. 章标题区

章标题区应紧凑，参考教材章节页，而不是 PPT 章节封面。

推荐结构：

```text
第一章  Discussion 的基本任务
────────────────────────
本章导读
□ 理解 Results 与 Discussion 的功能差异
□ 掌握一段分析必须完成的四个动作

1.1 Discussion 要回答的连续问题
正文……
```

要求：

- 章标题区一般占有效页高 12%–20%。
- 本章导读 2–4 项。
- 导读后直接进入正文。
- 若上一页剩余空间足以放下章标题、导读和至少 5 行正文，可在同页继续新章。

---

# 四、教学组件使用规则

组件必须基于语义触发，不能为了填版随机使用。

## 1. 本章导读

- 每章最多 1 个。
- 使用上下细线或浅色窄条。
- 不做大卡片。

## 2. 定义

- 用于必须被准确记忆的概念或最低标准。
- 每章通常不超过 1–2 个。
- 使用细边框和浅底色。

## 3. 重点

- 用于一节结束后的关键理解。
- 正文控制在 120 字以内。
- 不与定义框连续堆叠。

## 4. 示例

默认采用教材式缩进示例：

- 左侧细竖线。
- 上方小标签 Example A、Example B。
- 不使用大面积彩色卡片。
- 示例分析优先写成普通正文或上下细线的分析注释。

## 5. 自查清单

- 使用普通复选列表。
- 可以连续分页。
- 不把每个问题做成独立卡片。

## 6. 组件频率

- 普通页通常 0–1 个组件。
- 只有表格或长示例确有必要时，允许同页出现 2 个组件。
- 若某页组件面积超过有效内容区域 30%，应重新评估是否可以改回普通正文。

---

# 五、LaTeX 风格双线表

所有比较表、步骤表和数据表默认使用 `academic-table`。

强制样式：

- 不使用竖线。
- 不使用完整外框。
- 不使用大面积彩色表头底纹。
- 表格顶部双线。
- 表头下方一条单线。
- 表格底部双线。
- 普通数据行之间不加横线。
- 表头使用半粗体和品牌主色。
- 表格标题位于表格上方并左对齐。
- 表下注释使用 8.4–9pt 灰色文字。

跨页规则：

- 长表格允许跨页。
- 每页重复表头。
- 表格行不得跨页拆开。
- 不通过缩小字号把长表塞入一页。

# 六、分页与页面密度

## 1. 连续排版优先

- 不强制每章从新页开始。
- 新章可在上一章结束后的同一页继续，只要能容纳章标题、导读和至少 5 行正文。
- 不允许为“章节仪式感”制造半页以上空白。

## 2. 页面过空

正文页有效内容低于约 45% 时：

1. 允许下一节或下一章接续。
2. 拉入下一个完整语义块。
3. 缩小过大的标题区或组件外边距。
4. 合并被过度拆分的段落。
5. 不用图标、插画或空卡片填空。

## 3. 页面过满

正文页超过约 90% 时：

1. 将最后一个完整语义块移到下一页。
2. 调整段前段后距。
3. 允许表格跨页。
4. 增加页面。
5. 不缩小正文到 10.5pt 以下。

## 4. 孤行与标题控制

- 标题后不足 4–5 行正文时，标题移到下一页。
- 章标题不得孤立在页尾。章标题、本章导读、首个二级标题以及至少 4–5 行首节正文必须视为一个连续的章节开头；当前页容纳不下时，整组移到下一页。
- CSS Paged Media 至少应对 `.chapter-title` 设置 `break-after: avoid`，对 `.chapter-guide` 设置 `break-inside: avoid` 和 `break-after: avoid`，并保留首个二级标题的 `break-after: avoid`。仅给 `h2` 加规则不足以防止章标题与导读被拆开。
- 段落不得在下一页只剩 1 行。
- 短定义框和短示例不得跨页。
- 最后一页可以适度留白，但不得只剩一个结束标记或一句来源说明。

# 七、内容模型

`content-model.json` 应保留章、节、小节和正文块。

推荐结构：

```json
{
  "document": {
    "title": "学术写作中的批判性写作",
    "subtitle": "从 Critical Analysis 到 Critical Review",
    "type": "textbook_handout",
    "audience": "留学生与学术写作学习者",
    "language": "zh-CN",
    "source_note": "...",
    "cover_kicker": "学术学习资料",
    "cover_title": "根据文档主题生成的封面主标题",
    "cover_subtitle": "根据文档主题生成的封面副标题",
    "cover_topics": ["主题一", "主题二", "主题三"]
  },
  "chapters": [
    {
      "number": 1,
      "title": "批判性写作的基本内涵",
      "guide": ["...", "..."],
      "sections": [
        {
          "number": "1.1",
          "title": "Critical Analysis 的概念与表现",
          "subsections": [],
          "blocks": []
        }
      ]
    }
  ]
}
```

支持的 block 类型：

- `paragraph`
- `bullet_list`
- `numbered_list`
- `quote`
- `definition`
- `keypoint`
- `example`
- `example_analysis`
- `comparison_table`
- `data_table`
- `checklist`
- `source_note`
- `figure`

每个 block 必须保留 `source_refs`。

# 八、标准工作流

## 第 1 步：准备工作区并读取原始资料

```bash
mkdir -p work preview dist qa
```

## 第 2 步：生成 `source-map.json`

对于 PDF：

- 先渲染页面检查表格、图示和文字层。
- 不只依赖文本提取。
- OCR 仅作为最后手段。

## 第 3 步：生成 `content-model.json`

生成并验证：

```text
work/content-model.json
```

## 第 4 步：生成 `outline.json`

生成：

```text
work/outline.json
```

至少包含：

```json
{
  "entries": [
    {
      "level": 1,
      "number": "第一章",
      "title": "Discussion 的基本任务",
      "anchor": "ch1"
    },
    {
      "level": 2,
      "number": "1.1",
      "title": "Discussion 要回答的连续问题",
      "anchor": "s1-1"
    }
  ]
}
```

## 第 5 步：生成 `document-plan.json`

生成：

```text
work/document-plan.json
```

计划必须标记：

- 哪些内容使用普通正文。
- 哪些内容确实需要表格或组件。
- 哪些章允许与上一章同页接续。
- 哪些短块必须保持完整。

## 第 6 步：生成 `editable-handout.html`

```bash
python scripts/build_handout.py \
  --content work/content-model.json \
  --outline work/outline.json \
  --plan work/document-plan.json \
  --theme config/hls-theme.yml \
  --mode textbook \
  --cover-template assets/hls-cover-template-clean.jpg \
  --output work/editable-handout.html
```

生成 HTML 时必须同时生成封面页，并把固定模板图作为第一页背景。封面文案来自内容模型中的 `document.title`、`document.subtitle`、`document.cover_kicker`、`document.cover_topics` 或根据原始资料自动推断后的等效字段。

## 第 7 步：准备预览编辑器

```bash
python scripts/prepare_preview.py \
  --project /path/to/handout-project \
  --html /path/to/handout-project/work/editable-handout.html
```

## 第 8 步：启动本地服务器

```bash
python scripts/preview_server.py --project /path/to/handout-project
```

终端必须显示 `http://127.0.0.1:8765`。在浏览器完成修改后点击“确认并生成 PDF”。

## 第 9 步：等待用户确认

不代替用户点击确认，不在普通运行中自动创建批准标记。

## 第 10 步：保存批准版本

确认后生成：

```text
work/approved-handout.html
work/EDITOR_APPROVED
```

## 第 11 步：生成最终 HTML 与 PDF

服务器先生成分页探测 PDF，根据正文标题回填目录页码，再输出 `dist/teaching-handout.html` 和 `dist/teaching-handout.pdf`。

## 第 12 步：执行 QA

```bash
python scripts/qa_handout.py --project /path/to/handout-project
```

至少检查编辑器残留、标题锚点、目录链接、A4、可搜索文字、内部链接与书签；逐页视觉检查和 Contact Sheet 仍为完整交付的必做项。

```bash
node scripts/render_contact_sheet.js \
  /path/to/handout-project/dist/teaching-handout.pdf \
  /path/to/handout-project/qa/contact-sheet.png \
  /path/to/handout-project/qa/pages
```

# 九、自动修复顺序

遇到留白、溢出或 PPT 化问题时，按以下顺序处理：

1. 检查是否把普通正文错误转成了组件。
2. 将不必要的卡片还原为标题加正文。
3. 允许下一节或下一章接续在同页。
4. 调整内容块分页位置。
5. 合并或拆分语义段落。
6. 调整段前段后距。
7. 调整表格列宽或允许跨页。
8. 增加页面。

禁止优先缩小正文、压缩行距、删除原文或增加装饰组件。

- `teaching-handout.html`

### 批注修订版本命名

- 用户已经在 PDF 上批注后，修订版不得覆盖同名文件路径；应使用新的唯一文件名，例如 `teaching-handout_v2_章节分页修正版.pdf`。
- PDF 批注或附件预览界面可能按路径缓存旧快照。即使磁盘文件已替换，继续复用旧路径也可能让用户看到旧页面。
- 新版本交付前应同时核对：新文件名、新文件哈希、被批注页的重新渲染图，以及旧版是否已移入审核记录。

# 十一、质量验收清单

## 内容

- [ ] 有效正文保留率符合完整教材模式。
- [ ] 标题层级与原资料一致或更清晰。
- [ ] 关键术语、引用、数据、作者和年份未丢失。
- [ ] 原资料中的限定条件和来源说明已保留。
- [ ] 新增导语和总结没有超出原资料。

## 目录

- [ ] 目录包含章、节和必要的小节。
- [ ] 页码自动生成并与实际页面一致。
- [ ] HTML 目录可点击。
- [ ] PDF 目录可点击。
- [ ] PDF 生成书签大纲。
- [ ] 无重复锚点、空链接或错误跳转。

## 分页

- [ ] 每个章标题与本章导读位于同一页。
- [ ] 每个章标题与该章首个二级标题位于同一页。
- [ ] 首个二级标题后至少有 4–5 行正文或一个完整短内容块，不在页尾形成孤立标题。

## 版式

- [ ] 正文不小于 10.5pt。
- [ ] 表格正文不小于 9.5pt。
- [ ] 正文以单栏连续阅读为主。
- [ ] 组件未主导页面。
- [ ] 没有四宫格、步骤卡阵列或 PPT 式章节页。
- [ ] 没有大面积无意义留白。
- [ ] 表格为 LaTeX 双线表。
- [ ] 页眉、页脚和页码位置一致。

## 技术

- [ ] 正式 PDF 生成前存在有效 `EDITOR_APPROVED`，且哈希与批准 HTML 一致。
- [ ] 最终 HTML 不含工具栏、`contenteditable`、事件属性或调试标记。
- [ ] 封面背景、标题锚点、书签层级、目录链接和表格结构未被编辑破坏。
- [ ] HTML 可独立打开。
- [ ] PDF 可搜索文字。
- [ ] 表格跨页时重复表头。
- [ ] 所有页面无裁切、重叠和缺字。
- [ ] QA 报告无未处理的严重警告。

# 十二、回归测试标准

以学术写作资料为测试输入时，应达到：

- 第一页使用固定蓝橙封面模板，且标题根据文档内容自动改写。
- 目录至少列到二级，存在稳定结构时列到三级。
- 目录采用点线引导符并显示自动页码。
- 点击目录可以跳转到正文对应标题。
- 正文保留原始论证，不把每段压缩成一句卡片文案。
- 每章使用紧凑“本章导读”，不制作空白章节封面。
- 章标题、本章导读、首个二级标题和首段正文不得跨页拆散；回归测试应检查所有章标题的 PDF 目标页与该章首个二级标题目标页一致。
- Example A、Example B 使用教材式缩进示例，而非大面积卡片。
- 示例分析以连续正文为主。
- 常见问题使用正常标题与段落，不使用四宫格。
- 自查清单使用普通复选列表。
- 比较表使用 LaTeX 双线表。
- 不强制每章另起新页，避免半页空白。

# 十三、禁止事项

- 禁止在没有有效 `EDITOR_APPROVED` 时生成正式 PDF。
- 禁止让用户直接编辑目录、标题编号、锚点、页眉页脚或表格行列结构。
- 禁止在预览服务器中引入登录、云端保存、多人协作或复杂前端框架。
- 禁止擅自更换固定封面模板或重画封面背景。
- 禁止在封面上保留与正文主题无关的旧标题。
- 禁止只生成一级目录。
- 禁止手工写死目录页码。
- 禁止生成不可点击的假目录。
- 禁止把每个知识点拆成一页。
- 禁止把普通段落自动改为卡片。
- 禁止使用四宫格、步骤卡阵列和 PPT 式信息图作为默认正文结构。
- 禁止用大量图标代替真实信息层级。
- 禁止在表格中使用全网格线。
- 禁止用阴影和圆角堆叠制造设计感。
- 禁止为消除溢出持续缩小字体。
- 禁止跳过 PDF 渲染、目录链接检查和逐页视觉检查。
- 禁止把模型推断写成原资料事实。
